# docs/ —— 调研笔记与设计草稿

## 这个目录的职责

存放**知识**与**计划**，供人和 AI 会话读取接续。

> ⚠️ **这里放的是"笔记"，不是"决策"。**
> 每条结论都标注状态：**✅ 已验证** · **🟡 倾向（待评估）** · **🔍 待调研** · **❓ 未定**。
> 用户可以随时推翻其中任何一条——**工作前先看状态标记**。
>
> **"规矩"不在这里**，在根目录 `AGENTS.md`。

## 文件清单

| 文件 | 内容 |
|---|---|
| `asio-notes.md` | asio 机制 / 调参 / 已知坑；结论附 `文件:行` 与可执行实验命令 |
| `http-server-plan.md` | HTTP 服务器设计思路，**自顶向下逐层展开**（L0 协议 → L1 连接/流 → L2 执行与并发 → L3 观测 → L4 参数与自学习） |
| `modules.md` | C++ 模块在本仓库的布局与踩坑（分区 vs 独立模块、依赖 DAG、import 规则、全局模块片段） |
| `routing.md` | **路由手册** —— 与上面几份不同，它是**使用者手册 / 接口说明**（不是笔记）：§1 怎么声明与注册路由（`Get<>` / `req.param<>()` / `route_on`），§2–§6 pattern 语法、匹配语义、冲突规则、参数提取 |
| `vcpkg.md` | **工作区之外**的 vcpkg 根目录说明（怎么查端口、overlay 机制） |
| `changelog.md` | **变更史**（按时间倒序，只记"改了什么 + 为什么 + 怎么复核"） |

- `docs/routing.md` —— **路由手册**（使用者手册 / 接口说明）。
  写路由时查它：怎么声明（`Get<>` / `req.param<>()` / `route_on`）· 语法表 · 匹配语义 + 真值表 · 优先级与回溯 · 冲突规则 · 参数提取。
  刻意**不写**：与其他框架的对比、代码现状/未实现清单、符号行号 —— 那些在 `http-server-plan.md` §11.2。
- `docs/http-server-plan.md` §11.2 —— 路由的**设计取舍与调研**（与 `routing.md` 分工：那份是“怎么用”，这份是“为什么这么定”）

## 什么时候往这里加文件

- 有一块**知识**值得跨会话复用（机制、数值、实验方法）→ 加一份笔记
- 有一个**工作区外的目录/环境**需要说明（vcpkg 根、构建目录、扩展目录…）→ 单独写一份

## 写作约定

- 结论要**可复核**：给 `文件:行`，或给一段能直接执行的验证命令。
- **不要把话说死**：把**保留意见与风险**一起写上；被推翻时用"修订"小节标注，而不是直接改掉旧结论。
