# 编码纪律

> **这是写代码前要过一遍的规矩。** 不是现状说明，也不是历史记录 ——
> 想知道现状怎么设计，看 `http-server-plan.md`；想知道为什么变成这样，看 `changelog.md`；想知道怎么干活（证据、工具、提交），看 `AGENTS.md`。
>
> 本文与**具体代码解耦**：它约束“怎么写”，不描述“已经写了什么”。每条末尾的自检问句就是判据。

---

## 1. 注释：让代码自解释

| 该写 | 不该写 |
|---|---|
| **接口文档** —— 用途、前置条件、返回值语义、参数含义 | **怎么工作** —— 读代码就有 |
| **反直觉且一眼看不出原因**的一句话，且只讲“为什么” | **为什么这么设计**、**将来要改成什么** —— 进 `docs/` |
| | **“见 docs/…”索引** —— 文档路径会变，代码注释不该当索引 |

自检：**删掉它，代码还读得懂吗？** 读得懂 ⇒ 不写。**这条信息下次重构会失效吗？** 会 ⇒ 写进 `docs/`。

示范：

- 好 —— “`0` = 体已到尾；`out` 不得为空（否则 `std::invalid_argument`），失败抛 `BodyError`”（**契约**）
- 好 —— “夹到 `out.size()`：框架交给回调的载荷是输入的子区间 ⇒ 保证放得下”（反直觉，**一句话讲为什么**）
- 差 —— “这里不能用 `operator co_await`，因为 promise 的 `await_transform` 优先…”（五行机制说明 → 进 `docs/`）
- 差 —— “头部是文本，通道收的是字节 —— 在这里显式换看法”（下一条语句里的 `as_bytes` 自己就说明了）

## 2. 抽象：够用就好

- **不为标准库已有的语义造类型别名** —— `std::span` / `std::vector` 已经说清了自己是什么，包装只会多一层要记的东西。
- **不引入只有一种用法的间接层。**
- **能在编译期拦下的错，不留到运行期**：接口上就不提供那条路（例：“无体”的响应类型不给 `body()`），或用 `static_assert` 把要求写清楚。
  运行期只处理编译期看不见的事（“运行到这一步才成立”的状态约束）。

自检：**去掉这层抽象，调用方会变难写吗？** 不会 ⇒ 去掉。

## 3. 类型与字符串：语义写进类型

- **文本**用 `std::string` / `std::string_view`；**字节**用 `std::span<const std::byte>` / `std::span<std::byte>` / `std::vector<std::byte>`，
  **不给它们造别名**（见 §2）。`std::byte` 不参与算术 ⇒ 拿不走当字符用。
- **文本可以当字节看（子集），反过来不行**；两个方向的转换都要**具名且显式**（`as_bytes` / `as_text` 这类），不靠隐式转换。
- **字符串构造统一走 fmt**（`format` / `format_to` / `join` / `to_string`）；日志是唯一例外（走日志门面）。
  热点路径用 `format_to(back_inserter(out), …)` **直接往目标缓冲追加**，不产生中间 `std::string`。
- **协议文本与载荷字节不要混着返回**：该是文本的返回 `std::string`，该是字节的返回字节类型；混装在同一个缓冲里的地方，在边界处显式说明。

## 4. 错误：先分清“谁错了”

- **可恢复的失败走返回值** —— `std::error_code` + 自定义 `error_category`；
  **不要用 `bool` 表示“出错了”**（分不清几种失败，调用方也没法按原因分支）。
- **异常只留给“调用方写错了”** —— 前置条件、调用顺序、状态机顺序。这类抛出即 bug，应当在开发期就暴露；
  不要用它传“运行期可能发生”的失败。
- 错误消息是**能读的一句话**，且带上关键数字（尺寸、上限、状态码）。

自检：**这个失败是“环境 / 输入”造成的，还是“我们写错了”？** 前者返回值，后者异常。

## 5. 异步：只走既有的原语

- **不要给自定义类型加 `operator co_await`**：执行器的 promise 若有成员 `await_transform`，**标准规定它优先于 `operator co_await`** ⇒
  手写那套根本不会被调用（报错会指向 `await_transform` 的候选列表）。要让 `co_await 自己的对象` 生效，
  只能把它做成该框架的 async operation 对象；**默认不做** —— 代价是每次多一份协程帧分配、且与等待方脱离父子关系。
  入口写成显式方法即可（`co_await x.flush()`）。
- **跨等待点的动作必须经过带超时与取消的原语** —— 不要为了方便另开一条绕过超时的路（直连 socket / 阻塞调用）。
- **一段东西要么一次写完，要么写进同一个缓冲**：不要把逻辑上连续的块拆到多个等待点之间写，否则会和别的写交错。

## 6. 性能：分配与虚函数要克制

- **对象放调用方的帧里**（协程帧 / 栈），不放堆。
- **虚函数只出现在擦除边界**（需要跨擦除接口、跨模块那一层）；能静态分派就静态分派。
- 热点路径上**先问“这里有没有一次多余的分配”**，再谈别的优化。

## 7. 依赖与边界：跨界的动作集中在一处

- **第三方库不封 module**，直接 `#include`；也不替消费方 `export` 它 —— 消费方自己引入。
- **C ABI 的 `reinterpret_cast` 只出现在边界**，且集中在尽量少的地方；每处一句话点明“这是边界”。
- **模块的全局模块片段只放标准库与 C 头**（语言层面的约束，见 `modules.md`）。

## 8. 模块导出面：只导出使用者需要的

- **默认不导出**：模块接口单元里写 `namespace`，**不要**图省事写成 `export namespace … { … }` —— 那会把树、建树器、匹配器这类纯实现一起端给使用者。
- **逐个 `export` 真正给使用者用的符号**（类型、别名、枚举、工厂）；其余保持不可见。
- 同模块的其他 TU（实现单元 / 别的分区）**照样看得见**未导出的名字 ⇒ “自己要用”**不是**导出的理由。
- 出现在**导出声明**的签名里的类型也得导出（否则使用者拿到一个用不了的名字）；能让它不出现在公开签名里就更好（例：把细节数据收成私有，只留具名访问器）。
- **“内部件要测”不是导出的理由**：把编译期自检搬进**模块自己的实现单元**（编译即验证），不要为测试开后门。
- 收窄了导出面就要有护栏：让**消费方视角**的用例继续走 `import <主模块>;` 的公开面。

自检：**这个符号是使用者要写的吗？** 不是 ⇒ 不加 `export`。**我是为了方便测试才想导出它吗？** 是 ⇒ 搬测试，不是加 `export`。

## 9. 成员与访问控制段：先看什么，就把它放前面

**数据成员**（三档，由“这个类型是什么”决定）

| 形态 | 数据成员 | 访问控制 |
| --- | --- | --- |
| `class` | 全部**私有**，收在**末尾**单独一段 | 单独 `private:`（要给派生类用 ⇒ 单独 `protected:`，仍在末尾）；要暴露就**加访问方法** |
| `struct` **有方法** | 放在**最前面**，单独一段 | 显式写 `public:` —— 它与后面的方法段之间要有边界 |
| `struct` **没有方法** | 成员即全部内容 | **不写** `public:`（默认就是公开，写出来是噪音） |

⚠️ **有私有数据的一律写成 `class`**（`struct` 里不会出现私有数据）—— 判据：`struct` = 纯数据聚合（`http::Header` · `ResponseState` · `Settings`），`class` = 行为 + 私有状态。

**方法成员**：段的划分 = **（功能组, 可见性）**

- 方法按**功能成组**，**每组一个访问控制段** —— 不把“所有公开方法”堆成一段、“所有私有方法”堆成另一段（那样段只表达可见性、不表达功能）。
- 同一功能组里既有公开又有私有 ⇒ **拆成相邻的两段**（一段之内不混可见性）。
- 段之间**留一个空行**，让“段”在视觉上真的成形。
- `static constexpr` 常量与类型别名（`method` / `executor_type` 这类）放在**最前的单独一段**：它们是“声明性事实”，先读它们，再读状态与行为。
- **嵌套类型看它给谁看**：给使用者看的（`RequestParser::BodyStep`）放**最前**单独一段；纯实现细节（pimpl 的 `struct Impl`）随数据留在末尾 `private:` 里。
- 只读与读写方法（getter / setter）算**同一个功能组**，不再细分。

自检：**读这个类型的人第一眼该看到什么？** 行为（`class`）/ 数据（`struct`）—— 把对方挪到另一端。**段的边界等于功能边界吗？** 不等于 ⇒ 重新分段。
